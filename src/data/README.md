# `src/data/`

Schéma Drizzle, migrations et requêtes SQLite. Voir ADR 0001 pour la séparation entre Données de référence et Données précieuses.

- `schema.ts` : toutes les tables. Les Données précieuses n'ont **aucune** clé étrangère vers le Catalogue (un test le vérifie).
- `migrations/` : généré par `pnpm db:generate`, ne pas modifier à la main. La CI échoue si le schéma a changé sans migration.
- La base est **injectée** : `AppDatabaseProvider` (`features/startup/`) l'ouvre (expo-sqlite) et applique les migrations au démarrage avec `migrateSafely` (`migrate.ts`), puis les écrans la lisent avec `useDatabase()`. Les fonctions de ce dossier la reçoivent en paramètre (`AppDatabase`).
- Tests : `createTestDatabase()` (`testing/`) donne une base better-sqlite3 en mémoire, migrée avec le même paquet de migrations que l'app.
- Réglages : `getSetting` / `setSetting` (`settings.ts`), et `useSetting` pour une lecture réactive dans l'interface.
- Grilles : `catalogGrid.ts` donne les requêtes ; l'interface les lit avec `useReactiveQuery`, qui lit tout de suite puis relit (une seule fois par rafale de changements) quand l'une des tables lues change. `useLiveQuery` de Drizzle ne réagit qu'à la table principale et relit à chaque ligne modifiée.
- Sauvegarde : `backup.ts` lit toutes les Données précieuses (`readPreciousData`) et les remplace d'un bloc (`replacePreciousData`, en une transaction). `restoreBackup` range d'abord les données actuelles dans une Sauvegarde de sécurité (`SafetyBackupStore`, injecté : les fichiers sont dans `features/backup/`), ce qui permet `undoLastRestore`. Le format et sa validation sont dans `domain/backup.ts`.
- Classeur : `binder.ts` lit la Sélection du classeur (`readBinderSelection`), y ajoute en masse les résultats des filtres (`addToBinderSelection`, qui rend les Versions ajoutées pour « Annuler ») et les en retire (`removeFromBinderSelection`). L'ordre d'impression et les pages sont dans `domain/binder.ts`.
- Migrations (spec § 4.4) : `migrateSafely` écrit une Sauvegarde de sécurité de type `migration` avant toute migration en attente dont le SQL cite une table précieuse, puis laisse le migrateur de Drizzle tout appliquer en une transaction. Si la Sauvegarde de sécurité ne peut pas être écrite, rien n'est migré ; si une migration échoue, rien n'est modifié. Dans les deux cas, `MigrationError` dit quelle étape a échoué. `readPreciousData` lit les colonnes présentes dans la base, pas celles du schéma : une colonne qu'ajoute la migration est lue `null`. Une migration qui renomme ou retire une colonne précieuse doit garder cette lecture possible sur l'ancien schéma.
